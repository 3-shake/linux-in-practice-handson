## 問題1（CTF）: 気難しい預言者

`/opt/handson/ch03/oracle` は、あなた専用のフラグを知っている「預言者」プログラムです。
ただし、この預言者はたいへん気難しく、**実行のされ方**が気に入らないと口を開いてくれません。

```
$ /opt/handson/ch03/oracle
私は気分屋の預言者。論理CPUの間をふらふらと移されるのは好かん。
...
```

預言者の要望を聞き取り、本章に登場したコマンドで「実行のされ方」を整えて、
フラグを聞き出してください。`strings` でバイナリを覗いてもフラグは出てきません。

> ヒント: 3章「複数の論理CPUを使う場合」と「タイムスライスの仕組み（nice値）」。
> プロセスが動ける論理CPUを縛るコマンドと、優先度を変えて起動するコマンドがあります。
> どちらも root 権限は要りません。

## 問題2（修正）: CPU を譲らない同居人

この VM には、納品前のヘルスチェックで警告が出ています。

> WARNING: 日次集計ジョブ report の所要時間が、平常時の 1.4 倍前後に悪化しています

集計ジョブは手動でも実行できます。この VM の運用設計では論理CPU0 は対話作業用に
空けてあり、集計ジョブは論理CPU1 に固定して動きます。

```
$ time /opt/handson/ch03/report
```

原因を突き止めて、集計ジョブの所要時間を**恒久的に**（再起動しても元に戻らないように）
平常へ戻してください。ただし、この VM で動いているサービスはどれも業務上必要なものです。
**止める・無効化する・アンインストールするのは修復とは認められません**（判定が見ています）。

修復できると **30秒以内に自動で判定されて通知が届き、フラグも自動提出されます**。
待ちきれないときや途中経過を見たいときは手動でも判定できます。

```
$ sudo ch03-check
```

> ヒント: report を動かしながら top を眺めると、CPU を取り合っている相手が見えます。
> `ps -eo pid,ni,psr,comm` や `sar -P ALL 1 1` を使うと「どの論理CPUで」「どんな優先度で」
> 動いているかが見えます（本章の sar の実験そのものです）。
> 殺さずに解決する道具は、問題1ですでに使っています。
