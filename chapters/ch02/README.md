## 問題1(CTF): 眠り続けるデーモン

このVMには、あなた専用のフラグを計算しては**どこかに捨てている**常駐プロセス(デーモン)が
動いています。プログラムの実体は `/opt/handson/ch02/oracled` ですが、

```
$ /opt/handson/ch02/oracled
これは常駐して動くデーモンです。対話実行では何もしません。
すでに動いているプロセスの振る舞いを観測してください。
```

と、自分で起動しても相手にしてくれません。**すでに動いているデーモンを見つけ出し**、
それが**カーネルに何を依頼しているか**を観察して、フラグを回収してください。
`strings` でバイナリを覗いてもフラグは出てきません。

> ヒント: 2章「デーモン」。デーモンは `ps ajx` で見分けられます
> (親が init なので PPID=1、端末を持たないので TTY が `?`、独自セッションなので SID=PID)。
> 2章「プロセスの状態」。このプロセスはほとんどの時間スリープ(STAT=S)しています。
> 動いているプロセスは `strace -p <PID>` で「横から」観測できます(別プロセスへの
> アタッチには権限が要るので `sudo` を付けてください)。
> 表示が `...` で途切れて見えるときは、そのコマンドのオプションを調べてみましょう。

## 問題2(修正): 倒せないプロセス

`handson-immortal` というプロセスがこのVMで動いています。行儀が悪いので止めたいのですが、

```
$ pgrep -af immortal
$ kill <PID>        # 効かない
$ sudo kill <PID>   # 効かない
$ sudo kill -9 <PID># 消えた…と思いきや、すぐに復活する
```

と、どうやっても倒せません。原因を調査し、**恒久的に**無効化してください。
無効化できると **30秒以内に自動で判定されて通知が届き、フラグも自動提出されます**。
待ちきれないときや途中経過を見たいときは手動でも判定できます。

```
$ sudo ch02-check
```

> ヒント: 2章「シグナル」。`intignore.py` のように、シグナルを無視するプロセスがあります。
> どのシグナルが無視されているかは `cat /proc/<PID>/status` の `SigIgn` から読み取れます。
> 2章コラム「絶対殺す SIGKILL」。無視できないシグナルは何でしょう?
> それでも復活するのはなぜでしょう(このプロセスは何によって管理されているか)?
